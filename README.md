## For instructors: How this site works, and how to modify it

This site is a public, permanent home for EK125's per-class **Individual Practice Problems (IPP)** handouts, published as interactive [marimo](https://marimo.io) slide decks that execute in the browser via WebAssembly (Pyodide). No server, no sign-in, nothing for a student to install.

Each class gets one deck, one problem per slide, in the same order as the original paper handout. Unlike a lecture deck, nothing here is live-executed: every code snippet is hand-typed as a fenced code block inside a plain `mo.md()` cell, the same convention [EK125-C1-DePasquale-Slides](https://github.com/BU-EK125/EK125-C1-DePasquale-Slides) uses for its own "Your Turn"/hand-typed examples -- these are the practice problems themselves, so there's no answer to reveal live and no execution to worry about vanishing from the slide.

This repo works the same way as EK125-C1-DePasquale-Slides: it's a jupyter-book shell that only builds the intro page and the sidebar; each deck in the sidebar is a plain external link straight to its own exported marimo page -- clicking it navigates you there directly (full page, no iframe), the same as clicking any other external link.

**The pieces:**
- `slides/ClassN/*.py` -- the actual marimo notebook source (plus its `layouts/*.slides.json` and `custom.css`, which marimo needs alongside the `.py` file to render the slides layout and styling correctly). Edit these with `marimo edit slides/ClassN/ClassN_IPP.py`.
- `build_slides.sh` -- exports every deck in `slides/` to a self-contained WASM HTML bundle under `_slides_build/<DeckName>/`. This runs automatically in CI (both `pr-check` and the deploy workflow); you don't need to run it yourself, and `_slides_build/` is never committed (it's regenerated every build, and each bundle is tens of MB, so keeping it out of git history matters).
- `_config.yml`'s `html_extra_path` is what copies `_slides_build/<DeckName>/index.html` onto the built site at `<DeckName>/index.html`.
- `_toc.yml` -- one `url:` entry per deck, pointing at its full published URL (e.g. `https://bu-ek125.github.io/EK1225-IPP/Class2_IPP/index.html`). **Note:** because these are absolute URLs to the live site, sidebar links always go to the live site even when you're previewing a local `jb build` -- there's no local-preview equivalent for these links, only for the intro page itself.
- `.marimo.toml` -- repo-wide marimo settings applied to every exported deck (currently just `[display] theme = "dark"`). marimo searches upward from the current directory for this file, and `build_slides.sh` runs from inside each `slides/ClassN/` folder, so this one file at the repo root covers every deck.
- `colab_button.html` -- a small script (injected into every deck's `<head>` via each deck's `html_head_file` config) that adds a floating "🚀 Open in Colab" button, linking to that deck's `.ipynb` in `notebooks/`.
- `notebooks/<DeckName>.ipynb` -- a real Jupyter notebook export of each deck (via `marimo export ipynb`), generated by `build_slides.sh` alongside the WASM bundle. **Unlike everything else `build_slides.sh` produces, these ARE committed** -- Colab opens notebooks straight from GitHub over the network, so a real file has to exist in the repo at a stable path; it can't be a build-only artifact like `_slides_build/`. `pr-check` fails if you forget to regenerate and commit this after editing a deck.
- `strip_marimo_import.py` -- runs automatically (via `build_slides.sh`, right after each `marimo export ipynb`) to strip the dead `import marimo as mo` cell the exporter leaves behind, so the Colab notebook doesn't error on its first cell (marimo isn't installed on Colab). See the script's own docstring/comments for the exact cases it handles.
- `docs/` -- the original source PDFs each deck was built from, kept for reference. Excluded from the built site.

**To add a new class's deck:**

1. Author it with marimo (`marimo edit`), using the slides layout, and save it as `slides/ClassN/ClassN_IPP.py` alongside its `layouts/` and `custom.css`.
2. Add `html_head_file="../../colab_button.html",` to its `marimo.App(...)` config (see any existing deck for the exact placement) so it gets the Colab button too.
3. Add an entry to `_toc.yml`:
   ```yaml
   - url: https://bu-ek125.github.io/EK1225-IPP/DeckName/index.html
     title: "Class N: Individual Practice Problems"
   ```
4. Run `./build_slides.sh` locally and commit the new `notebooks/DeckName.ipynb` it produces, alongside your `.py` and `_toc.yml` changes.
5. Open a pull request rather than pushing directly to `main`. A GitHub Actions check (`pr-check`) runs automatically: it exports every deck, verifies `notebooks/` matches what you committed, and builds the whole book. Fix anything it flags before merging.
6. Once the PR is merged, GitHub Actions rebuilds and republishes the live site automatically -- no manual steps needed.
